# RB-08: バックアップ・復元

出典: `docs/implementation-plan.md` §7-7「復旧: 週次の論理バックアップを別ストレージへ。
復元リハーサル（別プロジェクトへリストア → `test:integration` / `test:conformance` 緑）を
Phase 1 で 1 回、以後四半期 1 回」。RPO 15 分 / RTO 4 時間（§7-5）。

## トリガー

- 定期の復元リハーサル（Phase 1 で 1 回、以後四半期 1 回）。
- 本番 DB の障害・データ破損が疑われる。

## 手順

1. Supabase の論理バックアップ（週次）から、**別プロジェクト**へリストアする
   （本番プロジェクトを直接上書きしない）。
2. リストア先に対して環境変数を切り替え、`npm run test:integration` と `npm run test:conformance`
   を実行し、両方が緑であることを確認する。
3. 復元されたデータの `audit_log` に対して連鎖検証（`verifyAuditChain` 相当。
   `npm run audit:verify`。task_020 の所有）を行い、連鎖が壊れていないことを確認する。
4. 実際に本番障害からの復旧が必要な場合は、RPO 15 分・RTO 4 時間を目標に、最新のバックアップ
   からリストアし、`workers/cron/` を含めた接続先の切り替えを行う。

## 人間承認が必要な操作

- 本番プロジェクトへの実際のリストア実行（不可逆操作。PO の承認を要する）。
- リハーサル結果が赤だった場合の対応方針の決定。

## 記録先

- リハーサルの実施日・結果（緑/赤）・所要時間は `docs/HANDOFF.md` に追記する。
- 実際の障害復旧はインシデント対応として `docs/incident-response.md` の分類に従い記録する。
