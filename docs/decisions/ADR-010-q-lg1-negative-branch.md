# ADR-010: Q-LG1 否定回答時の分岐

## ステータス

`proposed`

## コンテキスト

`docs/inquiries/lawyer-q-lg1.md`（Q-LG1）は、「参加者がアプリ内の導線から幹事名義の決済事業者アカウントへ直接支払い、運営者は資金の受入れ・保管・引渡しに一切関与せず、決済結果の照会と名簿への反映のみを行う」本構成が、資金決済法2条の2柱書の「弁済として資金を受け入れ、又は他の者に受け入れさせ…引き渡す」（為替取引）に該当するかを弁護士へ照会するものである。

`docs/research/premortem-risks.md` `R-LAW-01` はこの照会が「該当しうる」（否定的）と回答された場合の構造的リスクを次のように指摘する。

- 本ブリーフの適法性は L1（運営者の口座・決済アカウントを資金が経由しない）の一本足であり、否定回答時の退避設計が計画に存在しない。
- 残る経路は内閣府令1条の2第3号ニ（銀行等又は資金移動業者からの委託を受けて集金を行う構成）か、運営者自らの資金移動業登録だが、(a) 提携のリードタイムは未調査、(b) 登録の株式会社要件（運営主体の NonTurn LLC は合同会社）も未検証であり、いずれも現行のタスク日程には載っていない。
- `manual_confirm` 縮退構成（決済結果の反映を運営者システムが自動で行わず、幹事が決済事業者の管理画面を自分で確認して手動入力する構成）であっても、「幹事の受取先を指定して参加者に払わせる」という導線提供自体は変わらないため、この構成が本当に為替取引該当性を回避できているかは検証されていない。

`docs/gates/compliance-gates.json` の `GATE-LEGAL-FUNDS`（`required_for: phase2`）は本照会の結果でのみ `passed` にできるゲートであり、Phase 1（`ManualConfirmAdapter` のみを出荷）には要求されない。したがって本 ADR は **Phase 2（自動決済アダプタ: `PayPayOnlineAdapter` / `PayjpAdapter`）の可否**を扱うものであり、Phase 1 の名簿・台帳・ハーネス実装を止めるものではない。

## 決定（回答受領前の分岐設計。proposed）

Q-LG1 への回答は以下の3パターンのいずれかになりうる。各パターンでの対応方針を、回答受領前の時点で次のとおり定める。

### パターンA: 肯定回答（本構成は為替取引に該当しない）

`GATE-LEGAL-FUNDS` を `passed` とし、Phase 2 の決済アダプタ実装（task_026 以降）へ進む。この場合、以下は本 ADR の対象外。

### パターンB: 否定回答（該当しうる）— 本 ADR の主眼

以下3経路のいずれを取るかは、Q-LG1-B（`docs/inquiries/lawyer-q-lg1.md` 内の追加質問。第3号ニの提携先候補・株式会社化の要否・`manual_confirm` の該当可否を弁護士に確認する）への回答を踏まえて **PO（noritaka）が判断する**。本 ADR はこの3経路を事前に列挙し、判断材料を明確にするものであり、いずれかを採用と確定するものではない。

1. **第3号ニの提携先構成**: 登録済みの資金移動業者と提携し、その委託先として集金を行う。運営者自身の資金移動業登録は不要になる可能性があるが、提携交渉のリードタイムと提携先の選定は未着手であり、Phase 2 のスケジュールに与える影響は現時点で見積もれない。
2. **運営者自身の資金移動業登録**: 登録要件（NonTurn LLC は合同会社であるため、株式会社化が要件となるかは Q-LG1-B の回答待ち）が満たせるかを確認したうえで判断する。要件が重い場合、Phase 2 の実現可能性そのものが揺らぐ。
3. **`manual_confirm` 縮退構成での継続**: 自動決済を実装せず、Phase 1 と同じ `ManualConfirmAdapter`（幹事が事業者管理画面で確認した入金を幹事自身が記録する半自動）のみで運用を継続する。Q-LG1-B で「`manual_confirm` でも柱書該当の可能性が残る」との回答が得られた場合、この経路も無条件の安全策にはならない点に注意する（`docs/implementation-plan.md` §18-4 の18項）。

いずれの経路を取るかが確定するまで、`resolveProvider` は自動決済系プロバイダーを `off` のまま維持し、名簿・請求・台帳機能（Phase 1 スコープ）のみを提供する。

### パターンC: 期限超過（21日以内に無回答）

`docs/external-inquiries.json` の `lawyer-q-lg1` エントリの `default_decision_on_timeout` に従う。要旨: 決済導線は `manual_confirm` 縮退構成のみで運用を継続し Phase 2 へは進まない。並行して別の弁護士へのセカンドオピニオン照会または金融庁グレーゾーン解消制度の利用可否を検討し、いずれを取るかを PO が改めて判断してこの ADR を更新する。

## 影響

- Phase 1（task_011〜task_025）の実装・ハーネスはこの ADR の影響を受けない。決済アダプタ層（`PaymentProvider` インターフェース）は `P1`（決済事業者を決め打ちしない）の制約どおり、Phase 1 の時点で `ManualConfirmAdapter` のみを実装し、Phase 2 のアダプタ追加はこの ADR の帰結を待つ。
- パターンBの経路1・2はいずれも現時点で一次資料による検証（リードタイム・登録要件）が済んでいない。`[不明]` のまま Phase 2 のタスク分解を先行させない。
- この ADR は Q-LG1 / Q-LG1-B の回答受領後に PO が更新し、ステータスを `accepted`（採用する経路を確定）または `superseded`（サービス定義の再設計に伴い差し替え）へ遷移させる。

## 確信度

[設計] — `docs/research/premortem-risks.md` `R-LAW-01` の対応策（「Q-LG1 を弁護士照会の第1問として他と切り離して単独先行発注し、照会文に『否定回答の場合に取りうる構成をご教示ください』を含める。回答到着前に否定分岐の ADR…を起票し、Phase 1 の設計判断がその分岐で壊れないかを確認する」）に基づき、回答到着前の時点で起票する。3経路のいずれも一次資料未確認であり、本 ADR は分岐の枠組みを示すものであって経路の採用を決定するものではない。`docs/implementation-plan.md` の ADR 一覧（§13付近）の指定どおり `proposed` 止まりとする。
