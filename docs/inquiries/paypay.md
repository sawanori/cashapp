## 前提説明（質問文冒頭に付す）

私たちは、イベント幹事が参加者から会費・参加費を集める用途のLINEミニアプリを開発しています。幹事ご自身のPayPayアカウント（加盟店契約）へ参加者が直接支払う構成を想定しており、当方（開発・運営元）は資金の受入れ・保管・引渡しには一切関与しません。オンライン決済（Web Payment / Dynamic QR）の加盟店申込を前提に、以下をご教示いただけますでしょうか。

## 質問

### Q-PP1 会費徴収の取扱可能性

飲み会・懇親会・サークル活動などの会費徴収は、PayPayオンライン決済の取扱可能商材に該当しますか。貴社ページに「商取引ではない寄付や募金、投げ銭（チップ）など一部NG商材もございます」とありますが、イベント主催者が参加者から参加費を受け取る形態はNG商材に該当しますか。

### Q-PP2 イベント参加権販売の対価性

加盟店規約（オンライン決済用）は決済対象を「加盟店が販売する商品もしくは権利または提供する役務」の代価としていますが、イベント参加権の販売はこれに含まれますか。幹事が立て替えた飲食代を参加者から回収する形態はどうですか。

### Q-PP3 実店舗を持たない個人事業主の申込

オンライン決済の加盟店申込において、実店舗を持たない個人事業主（イベント主催を事業として行う個人）は申し込めますか。必要書類のうち、実店舗の外観・内観写真に相当するものは何を提出すればよいですか。

### Q-PP4 第三者による送金・受け取りのAPI照会

一般個人のPayPayアカウントに届いた送金・受け取りを、第三者のアプリケーションがAPIで照会する手段は提供されていますか（Open Payment API の公開ドキュメント範囲では見つけられませんでした）。

### Q-PP5 Webhookの署名・登録手順・リトライ・ペイロード

Open Payment API の Webhook に署名検証の仕組みはありますか。通知先URLの登録手順、リトライ回数、ペイロードのフィールド定義を教えてください。

### Q-PP6 支払者識別情報

`GET /v2/codes/payments/{merchantPaymentId}` のレスポンスに、支払者を識別できる情報（ユーザーID等）は含まれますか。含まれない場合、参加者ごとに個別の決済リクエストを発行する以外に本人を特定する方法はありますか。

### Q-PP7 継続課金・支払リクエストの法人限定

継続課金と支払リクエスト（Pending Payment）が「法人のお客様のみ」と記載されていますが、個人事業主は対象外という理解で正しいですか。

### Q-PP8 LINE×PayPay連携の外部API

2026年夏以降の LINE×PayPay 連携において、外部のLINEミニアプリから呼び出せるAPIやディープリンクは提供されますか。

### Q-PP9 加盟店APIキーの委託先保管の可否

加盟店の API シークレットキーを、加盟店ご本人ではなく開発・運営を受託した事業者（当方）が保管し、加盟店に代わってAPIを呼び出す構成は、貴社の加盟店規約上許容されますか。認証情報の第三者への開示・預託を禁止する規定がある場合、委託契約や権限分離（読み取り専用権限と決済実行権限の分離等）によって許容される余地はありますか。

### Q-PP10 紛争・売上取消の通知手段とAPI表現

チャージバックや不正利用の申立てなど、決済後に生じる紛争・売上取消は、APIやWebhookでどのように通知・表現されますか。加盟店が貴社管理画面で直接返金・取消を行った場合、当方のシステムがAPI経由でその事実を検知する手段はありますか。

### Q-PP11 Webhook送信元IPレンジの公式一覧

Webhook の送信元となるPayPay側のIPアドレス（レンジ）の公式一覧を提供いただけますか。受信エンドポイント側でIP許可リストによる入口防御を構成したいと考えています。

### Q-PP12 Webhook URLの変更手順とリードタイム

加盟店契約後にWebhook通知先URLを変更する場合の手順（セルフサービスか貴社対応か）と、反映までのリードタイムを教えてください。ホスティング環境の移行やドメイン変更が生じた場合を想定しています。
